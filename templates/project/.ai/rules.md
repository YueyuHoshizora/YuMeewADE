# 共用規則（每次開始工作時閱讀）

## 目錄

- 主專案：`Projects/<專案名>/`，含 `PROJECT.md`（專案台帳）與 `.ai/`（作業台帳、對話、記憶）。`.ai/` 不進 git。
- 工作副本：`Work/<專案名>/<作業ID>/`，由 YuMeewADE 在作業第一次送出指示時以 git worktree 建立，分支 `ym/<作業ID>`。**只在副本內修改**；收編到主專案由人透過畫面操作，AI 不自行 merge、不自行建立或刪除 worktree。
- 作業檔：`.ai/tasks/<作業ID>.md`，一個作業一個檔，不修改別的作業檔。啟動時會告知絕對路徑；它在主專案的 `.ai/`，已用 `--add-dir` 開放寫入。

## 作業檔怎麼寫

- frontmatter 的 `state` 只能是：`未開始`／`進行中`／`等待回覆`／`暫停`／`完成`。**不要自行寫成 `完成`**——步驟全部勾完後停下來，由人在畫面上確認完成。
- 需要人判斷時：把問題寫進 `question`，`state` 改成 `等待回覆`，然後結束這一輪。
- 「## 步驟」保持 3～5 個，做完一個勾一個 `[x]`；「## 已完成的工作」寫改了哪些檔、測了什麼；「## 下一步」寫接手的人／AI 該從哪裡繼續。
- 每次告一段落都更新作業檔；下一個 AI（可能是另一個 CLI）只會看到作業檔與文字對話的交接包，看不到你的工具輸出。

## 長對話

- 上下文接近上限（約 160k token）時，先把決定、理由、目前狀態、下一步、重要檔案位置摘要到 `.ai/memory/<日期>_<作業ID>.md`（不超過 2000 字），並在 `.ai/memory/INDEX.md` 加一行；再更新作業檔。
- 只讀最新的作業檔與必要的 memory，不要把整份記錄貼回對話。

## 權限

- 預設只能改副本內的檔案與主專案 `.ai/`；需要執行指令或碰其他目錄被拒絕時，把需求寫進 `question`，不要繞過。
- 刪除檔案前先確認是副本內自己建立的；大幅變更前先 `git commit`，保留復原方式。
